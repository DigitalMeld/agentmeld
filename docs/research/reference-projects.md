## Most important design distinction

Both projects separate an agent harness from the computer it controls. A containerized desktop does not establish that the agent itself, its native shell, or its credentials run inside that container. Rakazo constructs its Pi `Agent` in the server-side adapter. OpenMausBot spawns native Claude and Codex processes as children of the harness, then supplies computer tools as integrations. For AgentMeld's requested isolation, place the native agent process and its tool execution inside the execution environment, with the control plane outside it. This is an AgentMeld recommendation, not a claim that the reference designs promise that boundary. [Rakazo runtime](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/adapters/src/pi-runtime.ts#L256), [OpenMausBot Codex spawn](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/drivers/codex.ts#L696), [Claude spawn](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/drivers/claude.ts#L1464).

## Rakazo

### Source-verified structure

- **Separate runtime, computer, and durable-home interfaces.** `SandboxProvider` owns provisioning, preparation, execution, observation, actions, screen control, files, and workspace transfer. `AgentRuntime` and `AgentHomeStore` are separate contracts. This is a useful shape for a Rust orchestrator with replaceable runtime and infrastructure adapters. [Interfaces](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/adapter-kit/src/interfaces.ts).
- **Model flexibility is provided through Pi.** The runtime constructs Pi agents and resolves model credentials; this is not native Claude Code or Codex CLI integration. Keep native agent runtimes distinct from model endpoints in AgentMeld's domain model. [Pi implementation](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/adapters/src/pi-runtime.ts).
- **Computer providers are selected behind a factory.** Docker, E2B, Daytona, Box, desktop, and fake/none implementations are present. Missing configured remote credentials can yield an unavailable computer capability while the service still boots. [Factory](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/adapters/src/sandbox-factory.ts), [environment selection](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/adapters/src/sandbox-provider-env.ts).
- **Docker hardening and resource limits are explicit.** Container options drop all capabilities, set `no-new-privileges`, and apply memory/CPU/PID limits; current defaults are 2 GiB, 2 CPUs, and 2,048 PIDs. The supervisor receives the Docker socket, a privileged control-plane capability that must remain outside agent access. These source settings are not proof against escape or hostile multi-tenancy. [Container specification](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/infra/sandboxes/supervisor/src/computer-spec.ts), [Compose topology](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/infra/compose/docker-compose.yml).
- **Persistence is intentionally latest-only.** `LocalAgentHomeStore` declares `revisions: false`, stages a replacement directory, swaps it into place, and serializes writes. `restore` ignores the requested revision and checks out current state. Do not translate this into a promise of historical rollback. [Home store](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/adapters/src/home.ts).
- **Multiuser concepts are in the schema.** Organizations, members, spaces, space members, runs, computers, and execution leases are first-class relational records; Better Auth uses organization support. This offers a stronger starting reference for future collaboration than adding a share URL to a single-user process. Authorization correctness across all routes was not audited. [Schema](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/db/prisma/schema.prisma), [authentication](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/auth/src/index.ts).
- **Approval classification is a separate policy layer, with notable exemptions.** Shell, file writes, desktop actions, and browser actions are in an approval-exempt set; connector classification uses name patterns, while selected built-ins require approval. Do not copy this classification as a complete consequential-action boundary: a browser click or shell command can perform an external write. [Approval policy](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/packages/core/src/action-approval.ts).

### Maintainer documentation, not runtime-verified here

The README advertises persistent bots, routines, delegation, voice, integrations, desktop/mobile clients, and multiple computer providers. The computer-runtime document explains that Team Computer folders and screen leases are organizational/concurrency boundaries, not security boundaries: bots share an OS user and workspace. It documents independent browser profiles, human takeover leases, lazy desktops, workspace checkpoints, and replacing missing machines. These are valuable requirements to investigate, not evidence that all paths pass in production. [README](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/README.md), [computer runtime](https://github.com/elie222/rakazo/blob/83698c0de8eefab5993a84ed76cb81674a04ea32/docs/computer-runtime.md).

## OpenMausBot

### Source-verified structure

- **A canonical provider contract wraps different agent protocols.** `ProviderDriver`, `ProviderInstance`, and `ProviderAdapter` separate configuration/discovery, live instances, and turn execution. Capabilities include images, MCP tool classes, model switching, effort levels, and steering. `steer` returns accepted, refused, or indeterminate, preventing uncertain delivery from being automatically replayed. This is particularly useful for Claude Code/Codex parity without pretending their features are identical. [Contracts](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/contracts.ts).
- **Native integrations use structured protocols.** Codex uses `app-server` JSON-RPC; Claude uses bidirectional `stream-json`. The code handles approvals and provider-specific lifecycle events. AgentMeld should similarly normalize events and persist native continuation separately from the user-visible transcript. [Codex driver](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/drivers/codex.ts), [Claude driver](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/drivers/claude.ts).
- **The OpenAI-compatible adapter is not evidence of full Ollama computer support.** It supports a configurable URL/model and calls a shared chat runtime. That runtime implements a bounded tool loop and advertises custom MCP, peer-agent MCP, and Composio capabilities when tools are enabled, but does not advertise `computerMcp` in its capability record. It also uses an API-key availability gate. Treat Ollama as a dedicated compatibility/agent-loop task. [Adapter](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/drivers/openai-compat.ts), [chat runtime](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/drivers/openai-chat.ts).
- **Local VM is a containerized desktop.** The implementation validates runtime ownership, exact resolved image identity, mounted workspace, published-port safety, and container hardening before reuse. Docker/Podman paths enforce resources and restrict capabilities/namespaces/devices. The name alone must not be used to claim a per-agent hardware VM boundary. [Container implementation](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/container-computer.ts), [Local VM guide](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/apps/docs/content/docs/computers/local-vm.mdx).
- **Renewable execution ownership exists.** Local VM leases are keyed by bot/thread and pooled by validated target. This prevents two active runs competing for the same desktop within one harness. The implementation is in memory; this is not a distributed fencing mechanism. [Lease implementation](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/local-vm-lease.ts).
- **Transcript persistence has moved to SQLite.** `message-db.ts` uses SQLite WAL and delta inserts/updates, lazily migrates legacy JSON, and retains legacy files as backups. `store.ts` keeps per-instance continuation cursors private from wire projections. File comments can lag implementation: the top of `store.ts` still describes JSON transcripts. [Message database](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/message-db.ts), [store](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/store.ts).
- **Remote access uses paired sessions and coarse scopes.** The request-auth layer distinguishes local requests from remote/proxied sessions and checks origin and capability credentials. Session scopes are `admin` and `client`. This is useful pairing infrastructure, but insufficient evidence of per-agent contributor permissions or hostile tenant isolation. [Request auth](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/request-auth.ts), [sessions](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/server/sessions.ts).

### Documentation limits and licensing boundary

The README advertises messaging-style bots, channels, portable team packages, routines, voice, computer use, and connected apps. These were not exercised here. The custom-engine guide still claims OpenAI-compatible engines have no tool calls, contradicting the inspected chat-runtime implementation; capability decisions should follow source plus conformance tests. [README](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/README.md), [custom engines](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/docs/custom-engines.md).

Do not copy OpenMausBot's `enterprise/` code into AgentMeld. Its license prohibits redistribution and hosted use without a separate agreement. Its feature list places branding, workspace administration/hosted sign-in, budgets, and billing behind enterprise entitlements. Build AgentMeld collaboration and hosting boundaries independently, preserving the user's free self-hosted product intent. Third-party components and product trademarks have separate notices; root Apache metadata does not cover every file or dependency. [Licensing explanation](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/LICENSING.md), [enterprise license](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/enterprise/LICENSE), [feature inventory](https://github.com/milind-soni/OpenMausBot/blob/b054afda144436bc797ee7bbedfc38ce54938cbc/enterprise/FEATURES).

## Recommended patterns for AgentMeld

1. Separate model endpoints, native agent runtimes, execution environments, and computer/browser capabilities. Claude Code and Codex are agent runtimes; Ollama serves models and needs an AgentMeld tool loop.
2. Keep the Rust control plane small: lifecycle, scheduling, event persistence, policy, credential references, runtime supervision, and infrastructure adapters. Preserve protocol adapters as replaceable processes if that reduces native SDK coupling.
3. Start with one isolated execution environment per trust domain. Shared folders, display leases, and browser profiles are not tenant isolation. Add stronger VM isolation before hosting mutually untrusted contributors.
4. Persist normalized events and native continuation separately. Explicitly represent pending approval, interrupted, refused, and uncertain outcomes. Never replay a possibly completed external action merely because a transport disconnected.
5. Expose only capabilities verified for the selected runtime/model. Test tool calling, image input, interruption, approvals, continuation, and computer control independently for Claude Code, Codex, and Ollama.
6. Keep durable workspaces independent of disposable machines. Specify backup/restore and retention explicitly; browser profiles are sensitive state, and a latest-only checkpoint is not a backup history.
7. Design identity, workspace membership, per-agent grants, credential ownership, and run attribution now. Ship external contributor access later after cross-account authorization and isolation tests.
8. Use lazy desktops, idle suspension, bounded resource budgets, incremental transcript writes, and compact context. Rust overhead savings should be measured separately from browser and model memory/latency.

These recommendations are synthesis from the inspected designs. They do not adopt either project's code, UI assets, branding, or enterprise licensing model.
